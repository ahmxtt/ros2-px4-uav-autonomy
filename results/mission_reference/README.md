# Complete mission reference

`mission_reference.csv` is the full nominal mission the vehicle flies: a
multi-POI route through the `forest_map2` world, from the takeoff point back to
the takeoff point.

It is the input that makes an **armed** SITL run possible. Everything else in
`results/` is evidence *about* a run; this file is what a run consumes.

| | |
|---|---|
| Samples | 16 157 |
| Segments | 5 (3 legs, 2 orbits) |
| Total length | 428.651 m |
| Reference duration | 286.159 s at 1.5 m/s nominal |
| Frame | Gazebo world ENU, planar; reference altitude 2.0 m applied downstream |
| Starts at | world `(-50.025, -69.975)` — 0.035 m from the vehicle spawn point |

## Why it matters that it starts at the spawn point

The Offboard executor's settle guard refuses to fly to a first setpoint that is
far from where the vehicle is standing. A mission reference that begins mid-route
therefore cannot drive an armed run at all. This one begins at the spawn point,
so the full sequence — settle, mission, obstacle encounter, replan, rejoin,
completion — is reachable.

## Route

```
start (-50.0, -70.0)
  └─ 1  leg    start_to_poi1   101.99 m   ← the unknown obstacle sits here, at s ≈ 39.4 m
  └─ 2  orbit  orbit_poi1       88.18 m   2 turns, r = 6 m, ccw, about (15, 5)
  └─ 3  leg    poi1_to_poi2     50.79 m
  └─ 4  orbit  orbit_poi2       87.56 m   2 turns, r = 6 m, ccw, about (-30, 24)
  └─ 5  leg    poi2_to_start   100.14 m
back to start
```

## Columns

`segment_id, segment_type, segment_name, s_m, x_m, y_m, yaw_rad, curvature_1_per_m, v_ref_mps, t_ref_s`

`s_m` and `t_ref_s` are cumulative across the whole mission, not per segment.
`yaw_rad` is a world ENU heading (counter-clockwise from East).

## How to use it

```bash
# World ENU -> PX4 local NED setpoint stream, all five segments, 20 Hz
python3 tools/build_ned_setpoints.py \
    --trajectory-csv results/mission_reference/mission_reference.csv \
    --output-csv /tmp/setpoints_ned.csv
```

See [docs/installation.md](../../docs/installation.md) for the complete SITL
procedure.

## What this file is, and is not

It **is** a curated public copy of the canonical mission reference — byte for
byte the artifact the thesis runs consumed. The `sha256` in `manifest.yaml`
matches the canonical archive.

It **is not** raw data. Every number is derived: A* over an occupancy grid,
B-spline refinement, analytic orbit geometry, and a curvature-bounded speed
profile.

It **is not** regenerated by this repository. The public offline chain
reproduces a single-leg planning result exactly, but the multi-leg policy
planner, the orbit generator and the mission stitcher are not part of this
release. Treat this CSV as a fixed input, and verify it with `hashes.txt`.

## Related, and easy to confuse

- `results/planning/` — a **different**, standalone single-leg planning result
  used by the offline demo. Not segment 1 of this mission.
- `results/stop_replan_resume/mission_segment_window.csv` — an exact slice of
  this file (segment 1, s = 15.019…71.996 m), kept for the offline SRR geometry
  reproduction.
