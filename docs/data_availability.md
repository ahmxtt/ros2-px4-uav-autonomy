# Data availability

What this release contains, what can be recomputed from it, and what stays in
the private research archive.

> This is a **curated research-software release** with fully reproducible
> offline planning and Stop–Replan–Resume-geometry results, together with
> selected result summaries and evidence artifacts from controlled PX4 SITL
> runs.

*Stop–Replan–Resume* (SRR) is this project's name for the obstacle-response
sequence: stop, plan a local detour, resume the original mission.

The offline computations are independently reproducible. The canonical
live-run summaries are **not** independently recomputable from this release,
because the complete raw per-tick time series behind them are not included, so
those summaries cannot be recomputed from public files. What is reproducible,
and what is curated evidence, is stated per bundle below.

## Four classes of result, and they must not be mixed

**A. Deterministic offline computations on the Gazebo world.** Map generation,
global planning, line-of-sight reduction, B-spline refinement and the offline
motion-feasibility evaluation. These contain no randomness and regenerate
exactly from the public repository.

**B. Controlled PX4 SITL / Gazebo execution runs.** Nominal mission tracking,
ground-truth versus PX4 local-position consistency, and the online
Stop–Replan–Resume behaviour. These are measurements of specific flown runs.
SITL execution is not deterministic, so they cannot be regenerated, only
audited. They are the canonical thesis evidence.

**C. Published derived inputs.** The complete multi-POI mission reference. It
is neither a measurement nor a result: it is the geometric and kinematic input
that a run consumes. It is published in full, byte-identical to the canonical
artifact, and it is *not* regenerated by this repository.

**D. Public-release runtime validation.** Evidence recorded by pointing *this*
repository at a live PX4 SITL stack, to check that the extracted code still
works. It is a compatibility check on the release, not thesis evidence, and it
neither replaces nor updates class B.

## Per-bundle status

### `results/planning/` — class A, fully regenerable

| File | Content |
|---|---|
| `metrics.yaml` | A* planning metrics for the published leg |
| `trajectory_metrics.yaml` | B-spline refinement metrics and the speed profile |
| `path.csv` | the A* path, 1543 points, world ENU |
| `trajectory.csv` | the refined trajectory, 5108 samples, with clearance, curvature, speed |
| `control_points.csv` | the 53 spline control points |

Regenerate with `tools/reproduce_offline_demo.py`. The occupancy grid rebuilds
**byte-identically** from `sim/worlds/forest_map2.sdf`, and the A* path
regenerates **cell for cell**. Verified in CI.

### `results/stop_replan_resume/` — mixed

| File | Class | Content |
|---|---|---|
| `mission_segment_window.csv` | input | The window of the nominal mission reference around the event. This is the actual replanner input, published so the geometry can be recomputed. |
| `sensed_obstacle_metrics.yaml` | B, raw | The perception output the vehicle acted on, plus the ground truth used for evaluation only. |
| `event_log.csv` | B, raw | Timestamped state transitions of the live run, including the commanded hover setpoint. |
| `replan_runtime_metrics.yaml` | B, raw | Per-stage replan timings and the resulting geometry, as recorded online. |
| `resume_join_metrics.yaml` | B, raw | Resume anchor and join continuity, as recorded online. |
| `local_replan_astar.csv`, `local_replan_smoothed.csv` | B, raw geometry | The detour actually flown. |
| `verdict.yaml` | B, raw | Per-condition verdict of the run. |
| `srr_metrics.yaml` | curated | Summary assembled from the files above. |

**Recomputable from what is included:** the entire replan *geometry* — ROI
extents, cropped and patched map, A* detour, refined path, clearance,
curvature, lateral acceleration, and the rejoin continuity.
`tools/reproduce_srr_geometry.py` re-derives it and compares against the
recorded values; the A* node count and path length match exactly and the
refined path matches to the six decimals the CSV stores.

**Not recomputable:** detection latency, the stop-to-hover transition, the
online replanning runtime, tracking error and mission outcome. Those are
properties of a flown run.

**Not re-flyable from this release either.** `tools/build_srr_inputs.py` builds
every input the SRR node needs, but the resulting setpoint stream starts about
15 m into the mission because the published window begins there. That is enough
for a dry run against a live PX4 SITL stack, and it is enough for the offline
geometry reproduction, but an armed run from the spawn point is refused by the
executor's settle guard. Re-flying the armed mission requires the complete
multi-POI mission reference, which is retained in the private archive.

### `results/nominal_mission/` — class B, curated summaries

| File | Content |
|---|---|
| `tracking_metrics.yaml` | Setpoint-tracking error over the MISSION phase, n = 2922, recomputed from the run log under three explicit definitions |
| `state_consistency_metrics.yaml` | Ground truth versus PX4 estimate, airborne subset, n = 14 869 |
| `run_metrics_source.yaml` | The run's own recorded metrics, copied unchanged |

The tracking statistics were **recomputed** from the full per-tick log of the
run rather than copied, which is why all three error definitions are reported.
The per-tick log itself (3055 rows × 57 columns) is not published; it stays in
the private archive.

## What the hashes prove — and what they do not

Each bundle carries a `sha256sum`-compatible `hashes.txt`:

```bash
cd results/planning && sha256sum -c hashes.txt
```

**They prove** the files have not changed since the bundle was assembled, and
that the copy you hold is the copy the documentation describes.

**They do not prove** that a summary was correctly derived from the underlying
raw time series. A hash over `tracking_metrics.yaml` attests to that file's
integrity, not to the correctness of the statistics inside it. For class-A
results the independent check is the reproduction tool, which recomputes from
first principles; for class-B summaries no such check exists in this release,
because the raw logs are not published.

`manifest.yaml` carries a generation timestamp and is deliberately excluded
from `hashes.txt`, so a correct regeneration still verifies.

## What stays in the private archive

- Full per-tick logs of every live run.
- Ground-truth and PX4 local-position time series (~8 MB per run).
- The complete multi-POI mission reference (16 157 samples) and the derived
  NED setpoint stream.
- The full occupancy grids as stored PGMs, superseded here by regeneration.
- Development runs preceding the published ones. These were iterative runs
  under changing software and configuration, not repeated trials under a fixed
  protocol, so they cannot be pooled into a success rate and none is reported.
- Intermediate gate bundles (see [validation_gates.md](validation_gates.md)).

Available on reasonable request for academic review.

## Regenerating everything public

```bash
pip install -e ".[test]"
pytest                                                    # invariants + regression
python3 tools/reproduce_offline_demo.py  --output-dir /tmp/demo
python3 tools/reproduce_srr_geometry.py  --output-dir /tmp/srr
python3 tools/make_docs_figures.py                        # the three doc figures
for d in results/*/; do (cd "$d" && sha256sum -c hashes.txt); done
```
